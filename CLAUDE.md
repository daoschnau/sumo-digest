# CLAUDE.md

Контекст для Claude Code. Читать перед любым изменением в репозитории.

## Что это

Пайплайн, который дважды в неделю (или ежедневно — по конфигу) собирает новости
профессионального сумо из закрытого списка японских и англоязычных изданий, отдаёт
их модели, получает структурированный JSON и публикует выпуск на статическом сайте.

Полное ТЗ — `TZ.md`. Этапы — `ROADMAP.md`. Исходная спецификация агента, из которой
всё выросло, — `docs/sumo-digest-agent-spec.md`: правила транслитерации, стиля
и формата выпуска берутся оттуда дословно.

## Инварианты — нарушать нельзя

1. **У модели нет сети.** Не подключать `web_search`, `web_fetch`, MCP-серверы или
   любые инструменты в вызовы Anthropic API. Модель работает только с корпусом,
   который собрал Python. Это то, что делает закрытый список источников настоящим
   ограничением, а не пожеланием в промпте.
2. **Источники меняются только в `config/sources.yml`.** Не хардкодить URL в коде,
   не добавлять источники «для полноты». Asahi, Nikkei и Yomiuri исключены осознанно
   и навсегда.
3. **Sponichi и Hochi обходятся всегда и первыми.** Они дают основную фактуру.
   Разовая недоступность — сбой запроса, а не повод понизить приоритет.
4. **Ни одна ссылка в выпуске не может отсутствовать во входном корпусе.**
   Валидатор проверяет это жёстко. Не ослаблять проверку, чтобы «прошёл выпуск».
   Жёсткий отказ — только здесь и на схеме: там ломаются факты. Замечания
   линтера транслитерации публикацию не останавливают (см. ниже).
5. **Порядок блоков определяет код, не модель.** Сортировка по
   `(category_rank, importance, date)`.
6. **Таблица новых имён не попадает в текст выпуска** — только в `data/new_terms.csv`.
7. **Тесты не ходят в сеть.** Всё на фикстурах. Живая проверка источников — только
   `scripts/check_sources.py`, вручную.
8. **Тексты чужих статей не покидают прогон.** Ни в артефакты, ни в логи, ни тем
   более в репозиторий. Наружу уходит `build/corpus.meta.json` — ссылки, издания,
   даты, заголовки, объём. Цитировать факт со ссылкой на первоисточник — одно,
   раздавать копию статьи — другое.

## Команды

```bash
uv sync                                  # установка
python -m sumo_digest.run --dry-run      # полный прогон без публикации
python -m sumo_digest.collect --dry-run  # только сбор корпуса, без LLM
python -m sumo_digest.acceptance --latest # приёмка выпуска по чек-листу §7.3
python scripts/check_sources.py          # живая проверка листингов (руками, не в CI)
pytest                                   # тесты
ruff check . && ruff format --check .    # линт
```

## Переменные окружения

- `ANTHROPIC_API_KEY` — обязательна для шагов select/write.
- `SUMO_DIGEST_MODEL` — переопределяет модель для write.
- `SUMO_DIGEST_DRY_RUN=1` — не коммитить, не публиковать.

## Структура

```
config/sources.yml         закрытый список источников
config/translit_rules.yml  правила линтера транслитерации
schema/digest.schema.json  контракт выходного JSON
prompts/write.md           системный промпт писателя
prompts/select.md          системный промпт отборщика
prompts/translit_guide.md  руководство по транслитерации (§3 спецификации)
src/sumo_digest/           collect, extract, llm, validate, render, state, run
templates/                 issue.html, index.html, atom.xml
data/state.json            дата прошлого выпуска + seen_urls
data/new_terms.csv         накопитель новых транслитераций
data/issues/*.json         архив выпусков; сайт пересобирается из него целиком
site/                      результат рендеринга (GitHub Pages)
```

## Стиль работы

- Проект маленький: работаем прямо в `main`, без веток и пул-реквестов.
- Правки промптов в `prompts/` — только по явной команде. Формулировки там выверены
  по спецификации; переписывание «для ясности» ломает выходной формат.
- `config/translit_rules.yml` — то же самое: каждое правило соответствует пункту
  раздела 3.4 спецификации. Не сокращать и не обобщать.
- Подтверждённое имя закрепляется в трёх местах разом: таблица в спецификации →
  `prompts/translit_guide.md` пересобирается из неё → правило в
  `config/translit_rules.yml`, и строка уходит из `data/new_terms.csv`.
  После этого `python -m sumo_digest.render --relint` доносит новое написание
  до уже опубликованного архива.
- Новый код — с тестом на фикстуре. Изменение поведения валидатора — с тестом
  на отказ, а не только на успех.
- Не добавлять зависимости без причины, которую можно назвать одной фразой.
- Не превращать `run.py` в оркестратор с плагинами. Семь шагов подряд, читаемых сверху вниз.

## Чего делать не нужно

- Ретраить недоступный источник (спецификация запрещает прямо).
- Переводить японский текст до подачи модели.
- Просить модель проверить саму себя вместо детерминированной валидации.
- Публиковать выпуск с битой схемой или со ссылкой не из корпуса — никогда,
  ни с какой пометкой.
- И обратное: снимать выпуск из-за написания. Макрон в имени не делает выпуск
  ложным, а отменённый выпуск — это ноль вместо почти верного текста, причём
  в четверг утром чинить его некому. Замечания уровня 3 сначала уходят модели
  одной точечной правкой, остаток пишется в лог, выпуск выходит.
